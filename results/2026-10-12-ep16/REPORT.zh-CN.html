五组部署实验：KV 缓存、实际计算与完成时间

实验日期：2026 年 10 月 11–12 日。报告日期：2026 年 10 月 12 日。

在同一冻结长上下文负载和每组 16 DIE 的资源预算下，新增的 Non EP16 单实例取得最短的完整负载耗时：54.416 分钟。 旧统一基线中，AFD eager 比 Non EP8 快 24.84%；加入 EP16 后，Non EP16 又比 AFD eager 快 13.51%。因此，已验证的“AFD 优于 EP8”是那两套部署的实测结果，不能推广为 AFD 必然优于继续扩大专家并行的 Non 部署。五组均各运行一次完整负载，旧四组原始数值保持不变。

设计与可比条件

五组使用相同 W4A8 模型、公共 vLLM/Ascend 基线及已验证的 Compressor host 修复，各独占 16 DIE。负载为同一冻结清单的 256 个完整会话、9,078 条请求，原始输入 748,751,397 tokens，输出固定 1 token；客户端全局最多 16 条在途 HTTP 请求。Non 三组共用四域会话路由和 MBT8192，AFD 两组共用三域路由和 MBT32768。EP16 仅增加单实例 DP4/TP4/EP16 拓扑、四个 DP rank 的端点映射及必要记录路径；相对已审计的 Non EP4 命令，其余计算与性能参数一致。

容量如何影响历史复用

从 Non EP8 到 Non EP16，四个 KV 域及会话路由不变。EP16 的实际 KV 从 468.838 增至 562.675 GiB（+20.01%），缓存采用率从 83.9384% 升至 91.7196%（+7.7812 个百分点）；实际 prefill 减少 58,261,504 tokens（−48.45%），全程耗时减少 35.00%。这组比较支持更大的可用 KV 与更多历史复用、较少实际计算共同出现，但 EP8→EP16 同时改变了专家布局与通信，不能从这一次部署比较中单独估计 KV 容量的因果贡献。

AFD eager 的每个 A DIE 实际 KV 约 42.981 GiB，高于 EP16 的 35.167 GiB；AFD 只有 12 个 A DIE、3 个 KV 域，而 EP16 的 16 个 DIE、4 个域都承载 KV。本次测量中 EP16 的整机 KV 高 9.09%，每域会话压力也不同：冻结路由将 Non 的 256 会话均分为每域 64 个，AFD 三域分别为 85、86、85 个。AFD 每域约 57,100 个 KV block，EP16 每域约 46,718–46,719 个；总量分别约 171,299 和 186,874 个。EP16 相对 AFD eager 的缓存采用率高 4.1925 个百分点，实际 prefill 少 31,391,744 tokens（−33.61%），全程耗时短 8.502 分钟（−13.51%）。这说明 AFD 的较高单 DIE KV 容量不能代替整机容量、域数及路由压力来判断本负载的缓存效果。逐 DIE HBM、权重与 KV保留了每个设备的原值。

不能仅由“F 不存 KV”推导 AFD 总 KV 较少或 F 显存被浪费：F 承载专家也会释放 A 侧权重空间。这里观察到的是最终容量和负载分布的差异；MBT、通信、工作区等对显存分配的独立贡献尚未确认。HBM 使用量减去权重与 KV 的差额也不能直接标为单独测量的 activation/workspace。

bench 如何并发和调度

回放运行真实 AgentInfer analyzer、planner、依赖图和 SSE transport。冻结记录保留每个会话的原始 token IDs 及全部轮次；人工时间戳只重建同一会话的前后顺序，回放等待间隔设为零，本轮生成不回填下一轮。256 个会话同时进入依赖图，下一轮必须等上一轮发送与上下文依赖完成。

客户端准入器在所有已经就绪的请求中按冻结优先级选择，最多保持 16 个未完成的 HTTP/SSE 请求；没有按缓存域设置串行客户端队列。同一会话固定路由到一个 KV 域。Non EP16 的四域分别是同一实例的 DP rank 0–3；服务端各域独立使用实际观察到的 CompressorCheckpointAsyncScheduler，按每域 seq8、MBT8192 和可用 KV 组织执行。客户端 C16 与服务端每域 seq8 是不同层次的约束，异步调度也不会取消会话依赖。

逐请求 TTFT 从 AgentInfer 开始发送（正文序列化前）至首个生成 token，E2E 从同一起点至 SSE 完成；两者不包含该请求发送前的依赖与准入等待。全程从首个发送至最后完成。正式入口先确认端点空闲，对每个独立 HTTP 端点冷 reset，再保存各域原生计数和端点 metrics 基线。EP16 是 1 个 reset 端点、4 份域基线。完整 bench 方法与实现链接列出负载构建、准入和审计细节。

结论与证据边界

新 EP16 结果说明：在本次同一负载下，扩大 Non 专家并行也能获得比原 EP8 和两组 AFD 更高的整机 KV、更高的缓存采用、更少的实际 prefill 与更短的全程耗时。此前 AFD 相对 EP8 的 1.331× 加速仍是可信的既定部署比较，但不是 AFD 机制相对所有 Non 拓扑的普遍优势。EP16 相对 AFD eager 的全程加速为 1.156×；AFD F FULL graph 相对 eager 仍未显示额外全程收益。容量、采用、prefill 与耗时在五组上方向一致；专家布局、通信、MBT、域数和动态组批同时变化，现有实验不能把 1.156× 精确拆分为其中某一项的贡献。

EP16 的本地与远端审计覆盖 9,078 条 HTTP 与原生域结果、冻结输入 SHA、256 会话、四域路由、优先级、16 worker 修复 host、发压前有效环境及冷基线；配置差异记录仅发现 DP/设备范围与运行记录路径的预期变化。EP16 配置核对、EP16 结果与审计索引、旧四组原始指标和公开证据索引可追溯各项结论。正式运行完成后的自有服务停止记录在原归档保留；这不代表资源当前状态。

公开补充前的独立复核见 review.json：逐请求核对冻结身份、HTTP/native 一一对应、C16、优先级、会话依赖及全部指标，旧四组数值不变。该审计确认执行与统计一致性，不等同于全量数值精度测试。每组一次运行，不作统计显著性或普遍优势推断；后续已停止的显存归因诊断不纳入正式结果。
