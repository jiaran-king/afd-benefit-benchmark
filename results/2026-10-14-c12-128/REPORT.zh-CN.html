Prefix-on 收益场景：128 完整会话、C12 四组实验

实验与报告日期：2026 年 10 月 14 日。

在相同 16 DIE、prefix caching 开启的本次负载下，AFD eager 完成 128 个完整会话耗时 940.08 秒，比 EP4、EP8、EP16 分别少 51.77%、6.54%、21.65%。 四组各一次完整回放，合计 14,900 条请求全部成功。本次找到了符合目标的实测候选：AFD 对 EP4、EP8 有收益，对 EP16 也没有出现耗时劣势。

AFD、EP8、EP16 的 3,725 条请求逐条缓存采用完全相同，实际 prefill 均为 19,710,102 tokens。AFD 对这两组的优势是在等量实际 prefill 下观察到的系统完成效率差异。EP4 实际 prefill 为 50,688,150 tokens，比 AFD 多 30,978,048 tokens，缓存工作量也存在差异。四组均零抢占、零抢占重算；单次结果不代表稳定收益或普遍优势。

设计与可比条件

研究目标是在 prefix-on 的条件下，寻找 AFD 优于 EP4、EP8 且不慢于 EP16 的实际工作负载。先用 CPU 缓存模拟筛选候选，再冻结 源顺序前 128 个完整会话 / 全局 HTTP C12 进入实测。模拟不预测端到端时长，是否获益以四组设备实测为准。

四组在同一物理节点、同一 Pod 上顺序独占 16 DIE，使用相同 DeepSeek-V4-Flash W4A8 模型、tokenizer、公共 vLLM/Ascend 及已验证的 Compressor host 修复。实际正式顺序为 EP8 → AFD eager → EP16 → EP4；每组独立启动/profile、冷缓存 reset，并保存各域原生计数和端点 metrics 基线。每组正式回放一次，没有请求重试或结果拼接，没有 profiler。

数据集、会话并行与调度

本轮直接从已发布的 256 会话冻结负载 取源会话 0–127，保留每个会话全部轮次和原始请求字节：128 会话、3,725 请求、294,584,470 输入 tokens，每会话 9–75 轮，最大 prompt 216,178 tokens，输出固定 1 token。没有重新分词、截短历史、凑请求数或在实测后按收益挑会话。请求 SHA256 为 65e10b43838be7bdf1f7459a07d34f1a57b64d05fa75fbf2b94f46efed6e86a4；128 会话清单与原母集派生方法可复核。

128 个会话进入真实 AgentInfer 依赖图。客户端在已经就绪的请求中按预先冻结的优先级准入，全局最多保持 12 条尚未完成的 HTTP/SSE 请求；这就是 C12。后续轮次必须等本会话前一轮完成，没有新增轮次屏障或人为等待，本轮生成内容不回填下一轮冻结历史。客户端 C12、完整会话数 128、服务端每域最多 8 条序列，分别约束不同层次。

同一会话固定到一个 KV 缓存域，即保存并复用该会话历史的独立调度/缓存单元。按各会话最大历史长度降序、逐个分配给当前累计负载最小的域，事前生成均衡路由。Non 三组共用同一四域映射，每域 32 会话；AFD 三域分别为 43、42、43 会话。EP8 的域对应实例内 DP rank，EP16 的域对应同一实例的 DP rank 0–3。异步调度允许主机提交与设备执行重叠，未取消会话依赖，也不意味着所有域没有等待。

正式耗时从第一条实际 HTTP 发送到最后一条 SSE 完成，覆盖该区间全部依赖与准入等待，不含启动/profile、文件准备及冷 reset。TTFT 从发送前、正文序列化开始前计至首个生成 token；E2E 从相同起点至流完成，均排除请求发送前的依赖和准入等待。bench 方法仍适用，本轮并发上限为 C12。

AFD 相对 EP4、EP8 减少专家权重的重复驻留，为 A 侧留下更大的单 DIE KV 空间。在本次实测中，EP4 有 466 条请求采用缓存少于 AFD，其余请求相同；总计多做 30,978,048 个 prefill tokens，约为 AFD 实际 prefill 的 157.17%。容量压力与这项额外工作量相符，但专家布局、通信和组批也随部署变化，不能将全部 51.77% 时长缩短精确归给缓存。

EP8、EP16 则与 AFD 的 每一条请求输入及缓存采用均相同，并非仅总命中率碰巧一致。EP16 比 AFD 多 46.91 GiB KV，本次没有因此少做 prefill。于是，AFD 在保有对 EP4 缓存工作量优势的同时，没有承担相对 EP16 的额外 prefill。对 EP8、EP16 的收益体现为当前配置完成相同实际 prefill 的系统效率差异；等量 token 仍不等于完全相同的 FLOPs、批形状或执行轨迹。

这也说明容量优势是否兑现取决于工作集。此前 256 会话 / C16 五组实验中，EP16 比 AFD 少做 31,391,744 个 prefill tokens，并且完成更快。本轮不改写旧结论：负载、并发和对子集重建的路由均已变化，无法把收益反转归结为“只调小 C”或单一缓存阈值。两组实验共同显示，AFD 的收益需要结合历史复用压力和实际执行效率判断。

复核结论与边界

这次比较的负载身份、完整会话、模型/软件、16 DIE 资源、C12、会话依赖、冻结优先级、亲和落点、有效异步调度与原生计数均通过核对；未发现影响本次既定部署比较的执行或配置偏差。结果支持：在本次 prefix-on、128 完整会话、C12 的 workflow 下，AFD eager 同时优于 EP4、EP8、EP16。 原始 256 会话结果独立保留，未被替换或合并。

适用边界仍然明确：每组一次、固定顺序，同机排除了跨机器差异，但没有通过反顺序重复排除时间与系统波动；尤其对 EP8 的 6.54% 收益还不能称稳定。MBT、域数、通信与动态组批没有做因素隔离，也未证明各 Non 拓扑已达到最优。此次精度检查沿用既定版本证据，并验证实际加载身份、输出 token 与流完整性，没有新增全面数值精度评测。review.json记录设计审阅、数据证据与限制。

发布前还核对了准备清单：其中几项描述性的 selection、coverage、length distribution 字段继承了母集统计。原始清单保留；公开 128 会话清单依据完整索引与已发布母集的原始行重算，正文、输入哈希、优先级、路由、发压参数和性能记录均未改变。

四次正式回放各完成一次。首次 AFD 在发压前因沿用旧记录用途断言失败，0 条正式请求；仅修正记录断言后，经离线检查并获用户明确批准补跑一次，成功 AFD 使用新 run ID v2。失败记录独立保留。首个模型启动至最后服务清理 118.61 分钟，未超过原 135 分钟预算。运行历史、成本审计与证据包身份可追溯。清理时自有模型/回放进程已停止，任务与数据按约定保留；此记录不代表资源当前状态。
