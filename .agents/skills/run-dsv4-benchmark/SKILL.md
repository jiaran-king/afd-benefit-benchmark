# DeepSeek V4 性能实验

使实验回答用户指定的问题：运行指定模型、源码和执行路径，保留足以复盘的实际配置与证据。用户已批准的范围直接沿用；仅对未经授权的关键偏离补充决定。

## 选择基线

先明确实验问题、比较变量、负载、样本量与完成标准，再定位对应实验的固定记录。阅读[实验定义](../../../experiments)、[版本与补丁](../../../environment/README.md)、[复现步骤](../../../docs/reproduction.md)及[扩展规则](../../../docs/extending.md)。资料中的历史建议不等同于本次批准条件。

`benchmark.py` 当前执行冻结的五组 256/C16 实验。128/C12、其他版本或新拓扑应使用各自已核对的执行入口；换 run-name 不会切换实验定义。新实验使用独立目录与 run ID，保持历史结果冻结。

## 核对身份与 MoE 路径

按[关键参数与快照约定](references/critical-parameters.md)检查：

- **源码**：vLLM、Ascend、AFD 的准确提交、未提交修改/补丁、实际导入来源及 native 库。版本字符串、分支名称、目录名称不能代替身份。
- **模型**：实际挂载的型号、架构、量化、权重来源及 config/tokenizer 指纹。服务别名不能证明模型身份；元数据 hash 不能冒充完整权重校验。
- **MoE**：设备、EP/DP/TP、MR、融合开关的配置优先级与生效值、CANN 组件及选择器源码。区分 MegaMoE、DFC、普通 MC2/AllToAll 和 AFD/CAM。

以本次批准条件整理 `expected.json`；从真实命令、环境、文件和生效配置独立采集 `actual.json`。快照字段含义与证据来源须可核查，未知值保持未知。对没有 Git 元数据的 source export，使用原来源核对记录和文件指纹。CANN/Ascend 版本变化后重新查开关语义。

在仓库根目录执行只读比较：

~~~bash
python3 .agents/skills/run-dsv4-benchmark/scripts/check_experiment_config.py \
  --expected /path/to/expected.json --actual /path/to/actual.json
~~~

`config_match` 只表示两份完整快照匹配。脚本不连接设备、启动服务或证明算子已经执行；关键身份/参数缺失、变更或无法解析时输出 `needs_review`。部署端口和输出路径放在 `deployment`，避免当作性能差异。

## 执行与验收

1. 启动前核对关键条件；明确区别会改变**算子路径**、**执行/缓存行为**和**测量数值**的参数。按本次问题选择必要样本，复用匹配的历史证据。
2. 获准的最小启动后，核对实际导入文件、加载的 native、最终配置和自动回退。涉及 MoE/graph 实现结论时，需要对应的最小运行证据；不要仅凭开关开启宣称实际执行，也不要求每轮性能测量都开 profiler。
3. 正式测量沿用批准的矩阵与观测设置。确认自然专家路由、缓存起点、性能观察器及额外同步状态。profiling/功能诊断与正式性能结果按实际用途标注，保留两组的必要差异。
4. 使用现有执行入口完成回放、审计与清理；失败保留现场，再次运行用新 ID，按既有授权处理，不拼接结果。只停止本 run 拥有的进程和资源。
5. 归档实际配置、输入与源码身份、关键指标和证据索引。结论前置，解释必要差异；区分历史原始证据和后续补采。公开材料遵循[仓库发布范围](../../../docs/publication.md)，外部发布沿用本次明确授权。
